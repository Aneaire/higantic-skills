# Maintainer rules

- Keep this repository public-only. Never add secrets, credentials, customer data, unpublished vulnerabilities, private implementation details, internal URLs, local workspace paths, or content copied from private sources unless it is explicitly approved for this public skill.
- Each skill lives at `skills/<name>/`, contains `SKILL.md`, and has frontmatter whose `name` matches the directory and whose `description` clearly states when the skill applies.
- When adding a public skill, add its reviewed slug, label, and description to `SKILL_CATALOG` in `higantic_skill_install.py` so authenticated CLI users can opt into it; keep the slug synchronized with `skills.sh.json` and cover installed, declined, accepted, and noninteractive behavior in tests.
- Keep interactive CLI output concise and human-readable; expose structured output only through explicit `--json`, keep diagnostics read-only, and test that profile listings, diagnostics, hints, and child-process errors never disclose stored credentials or terminal control sequences.
- Keep each installable skill self-contained with only `SKILL.md`, `README.md`, runtime `scripts/`, and `references/`; keep maintainer-only tests and evals in the repository-level `tests/` and `evals/` directories.
- Every skill declared in `site/v1/manifest.source.json` must package `scripts/fetch_live_reference.py`, `references/live-reference.json`, and `references/live-reference-fallback.json`, then run/read the locally rendered reference first. Local safety, approval, credentials, destinations, destructive actions, and sharing rules always win.
- Build public references from the maintained source manifest with `node scripts/build-site.mjs`. Only `https://skills.higantic.com/v1/manifest.json` and exact same-origin `https://skills.higantic.com/v1/references/<slug>.json` endpoints are allowed. Agent-consumed remote Markdown, prose, instructions, URLs, shell commands, and unknown identifiers are forbidden.
- Keep each remote reference closed-schema and ASCII-only: fixed fields, local identifier allowlists, fixed scope identifiers, booleans, nonnegative safe integers, semantic versions, and UTC timestamps only. Enforce duplicate-key rejection and 64 KiB publisher/client limits. SHA-256 is a consistency check, not content authentication.
- Fetchers must load their per-skill version and exact URLs from canonical `references/live-reference.json`, disable environment proxies, send no credentials or environment-derived headers, validate before rendering, and never print remote bytes. All explanations come from fixed installed renderer text.
- Use progressive disclosure: make `SKILL.md` concise and operational, then place detailed contracts and API references under `references/`.
- Repository code and documentation remain the source of truth. Generated HTML artifacts are derivative, disposable review surfaces with visible provenance.
- Coordinate public skill changes with the supported HiGantic API. Do not document speculative routes, scopes, packages, flags, or behavior; compatibility changes require corresponding documentation and tests.
- Preserve environment-only API keys, explicit opt-in public sharing, optimistic concurrency, output redaction, and confirmation gates for destructive or sharing operations.
- Run the deterministic Node site build/checks, unit tests, Python compilation, source/generated JSON validation, and `scripts/validate_repository.py` before release; remove generated `dist/`, `__pycache__/`, and `.pyc` afterward.
- A release is ready only when public wording is accurate, links resolve, examples are safe, the skill is self-contained, required checks pass on Python 3.9 and current Python, and no private-only material remains.
